# Contracts

One OpenAPI file per service: `api/<service>.yaml`. The contract is written
**first**, and both sides are generated from it:

| From `api/<service>.yaml` | Generated by | Into |
|---|---|---|
| the Go server interface and models | oapi-codegen (`scripts/generate.sh`) | `services/<service>/internal/api` |
| the TypeScript types the frontend calls with | openapi-typescript | `b2b-frontend-template/packages/api` |

CI fails in either repo if generated code differs from what its contract
produces, so neither side can drift from the file here.

## Keeping the frontend in step

When a file here changes, copy it to the frontend and run its generator there.
A frontend caller that no longer fits then fails to compile.

## Conventions

- `snake_case` fields, plural resource names, `/v1/` prefix per service.
- Every error response is the `Error` schema: `{ code, message, fields? }`.
- `security: [bearer]` at the top; health endpoints are not in the contract.
- Cursor pagination, never offset; an `Idempotency-Key` header on every create.
