# Services

One Go service per directory, each owning one Postgres schema.

`organization/` is the template. Everything a service needs is already in it:

```
services/organization/
  main.go                 config, logging, pool as its own role, health, graceful shutdown
  queries/*.sql           SQL, one "-- name:" block per query
  sqlc.yaml               queries + ../../migrations/organization -> internal/store
  oapi-codegen.yaml       ../../api/organization.yaml -> internal/api
  internal/store/         generated by sqlc. Never edit.
  internal/api/           generated by oapi-codegen. Never edit.
  internal/server/        the API: implements the generated interface
api/organization.yaml     the contract, written first
migrations/organization/  the schema, one file per change
```

## A new service

1. Add it to `pkg/db/services.go`. That gives it a schema and a role.
2. Copy `services/organization/` to `services/<name>/`. Change `const name` in
   `main.go`, the paths in `sqlc.yaml`, and the package imports.
3. Write `api/<name>.yaml` and the first `migrations/<name>/00001_*.sql`.
4. Run `scripts/generate.sh`.
5. Copy the `organization` block in `deploy/docker-compose.yml`.

## The rules, and what enforces them

| Rule | Enforced by |
|---|---|
| A service reaches only its own schema | Postgres roles (`pkg/db.Bootstrap`), tested |
| Services never import each other | `internal/repocheck` |
| Every service has a schema, a role and a contract | `internal/repocheck` |
| Every query names `org_id`, or says `-- global: <reason>` | `internal/repocheck` |
| Every table follows [the table conventions](../docs/tables.md) | `pkg/db.CheckConventions`, in CI |
| Generated code is never edited by hand | CI regenerates and fails on any difference |
| Every error is `{ code, message, fields? }` | `pkg/httpx`, and the contract's `Error` schema |
| Writes carry an org and an actor | `db.Cluster.Tx`, and the provenance trigger |
| Every API request carries a valid token; health is public | `auth.Require` around the API in `main.go` |
| A token only reaches its own org | `auth.RequireOrg` in each handler that takes an `org_id` |
| Every endpoint is rate limited, one line each | `server.Limits` + `ratelimit.Routes`; `PerAddress` in front of auth |
| Admin actions are audited: one call, ids only, fails rather than drops | `audit.Recorder` passed to `server.New`; the audit service owns the append-only store |
| A service calls another service with its own token | `auth.IssuerTokenSource` + `auth.Authorize`; `auth.RequireService` on internal endpoints |
| A customer secret is encrypted under that org's key; only identity, rtc, messaging, calendar and integrations decrypt | `envelope.Keyring` over `envelope.OrgKeys` + KMS; see [docs/encryption.md](../docs/encryption.md) |
| Email goes through the notification service's outbox: one call, retried, never silently dropped | `email.Sender` (`email.NewClient`); templates in `pkg/email`; bounces mark the address |
| Every response carries the security headers; only the app origins may call from a browser | `httpx.SecurityHeaders` and `httpx.CORS` outermost in `main.go`, origins from `config.AppOrigins` |

## Rate limits

A new endpoint gets one line in its service's `Limits` table, binding it to a
rule from `pkg/ratelimit/defaults.go` and what to count by:

```go
"POST /v1/invites": ratelimit.On(ratelimit.InviteSend, ratelimit.ByMembership),
```

Over the limit, the client gets 429 with `Retry-After` and the `rate_limited`
envelope. For sign-in style endpoints, where only failures should count, use
`limiter.Check` before the attempt and `limiter.Penalize` when it fails.

## Generated code

```sh
scripts/generate.sh
```

sqlc runs from its Docker image (it needs cgo); oapi-codegen is a Go tool
pinned in `go.mod`. CI runs the same script and fails if anything changes.

## Running one locally

```sh
docker compose -f deploy/docker-compose.yml up organization
curl localhost:8081/readyz

# a token for a member of an org, from the local stub issuer
TOKEN=$(curl -s -X POST localhost:8093/token -d '{"org_id":"<uuid>"}' | jq -r .access_token)
curl -H "Authorization: Bearer $TOKEN" localhost:8081/v1/organizations/<uuid>
```

Or outside Docker, bringing its own schema up to date on start:

```sh
DATABASE_URL="postgres://localhost:5432/b2bapp?sslmode=disable" \
DB_LOCAL_PASSWORDS=true MIGRATE_ON_START=true PORT=8081 \
AUTH_ISSUER=b2bapp-local AUTH_JWKS_URL=http://localhost:8093/v1/jwks \
  go run ./services/organization
```

## Seeing what a service is doing

Every service logs one JSON line per request with its `request_id` and its
trace. A request that arrives with a W3C `traceparent` (or Google's own
trace header) stays in that trace; one that does not starts a new one. Every
call to another service through `auth.Authorize` passes the trace on as a
child span, so in Cloud Trace one trace shows every hop, and in Cloud
Logging one click shows every line of it (`GOOGLE_CLOUD_PROJECT` names the
project the trace lives in).

`GET /metrics` on each service serves request counts by route and status,
latency histograms, requests in flight, and the process's goroutines, memory
and garbage collection, in the Prometheus text format. It answers only a
direct scrape: a request that came through the load balancer gets 404.

```sh
curl -s localhost:8084/metrics | grep http_requests_total
```

In the cloud, each service has a Cloud Monitoring dashboard (requests by
response class, latency percentiles, CPU, memory, instances) and the data
stores share one (Postgres and Redis), all in `deploy/terraform/monitoring.tf`.
